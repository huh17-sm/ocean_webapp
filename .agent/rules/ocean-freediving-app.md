# 프로젝트 규칙 (Project Rules & Guidelines)

## 0. 기본 원칙 (Beginner Friendly)
- 나는 코딩을 모르는 초보자(Non-coder)다. 모든 설명은 **'비개발자 용어'**로 풀어서 한국어로 설명해라.
- 코드를 수정할 때는 **"이 코드가 왜 필요한지"** 한 줄 요약을 반드시 덧붙여라.
- 복잡하고 화려한 기술(Optimization)보다, **느려도 좋으니 확실하고 안전한 코드**를 작성해라.

## 1. 데이터베이스 안전 수칙 (DB Integrity)
- **삭제 금지:** 사용자의 데이터(예약, 결제 내역)를 `DELETE` 하는 쿼리는 절대 내 허락 없이 실행하지 마라. 대신 `status = 'deleted'` 처럼 상태값만 변경하는 방식(Soft Delete)을 제안해라.
- **트랜잭션 필수:** 결제와 횟수 차감처럼 2가지 이상의 작업이 동시에 일어날 때는 반드시 **트랜잭션(Transaction)**을 사용해라. (하나라도 실패하면 모두 취소되도록).
- **데이터 구조 변경:** 테이블 컬럼을 추가하거나 타입을 바꿀 때는, 기존 데이터가 날아가지 않는지 2번 체크해라.

## 2. 관리자-사용자 연동 원칙 (Single Source of Truth)
- **동기화 보장:** 관리자 페이지의 데이터와 사용자 페이지의 데이터는 무조건 **하나의 DB 테이블**을 바라봐야 한다. (하드코딩 금지)
- **검증 절차:** 관리자 기능을 구현할 때는, 반드시 **"이 기능을 쓰면 사용자 화면(마이페이지)에서는 어떻게 보이는지"**를 함께 시뮬레이션하고 설명해라.
- **실시간성:** 예약 상태가 변경되면(예: 확정 -> 취소), 새로고침 없이도 UI에 반영되도록 Supabase의 실시간 기능(Realtime)이나 상태 관리 로직을 확실하게 짜라.

## 3. 코드 스타일 및 구조 (Spaghetti Prevention)
- **파일명 규칙:** 파일 이름은 기능이 명확히 드러나게 지어라. (예: `ReservationComponent.tsx` (X) -> `ReservationListForUser.tsx` (O))
- **주석 필수:** 모든 주요 함수(Function) 위에는 이 함수가 무슨 일을 하는지 **한글 주석**을 달아라.
- **재사용:** 똑같은 코드를 여러 번 쓰지 말고, 공통 컴포넌트로 분리해서 관리하기 쉽게 만들어라.

## 4. 에러 방지 워크플로우 (Error Prevention)
- 코드를 다 짠 뒤에는 반드시 **[테스트 체크리스트]**를 나에게 제공해라.
  (예: "1. 관리자 페이지에서 횟수 차감 버튼 누르기 -> 2. 사용자 마이페이지 가서 줄어들었는지 확인하기")
- `project_spec.json` 파일을 항상 참조하여, 기획 의도에서 벗어나지 않도록 해라.
